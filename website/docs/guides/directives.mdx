# Custom Directives

A custom directive is a `directive @name` declaration paired with a schema transformer that you apply to the application schema. To validate input fields and arguments, see [Input Directives](./input-directives.mdx); the API there is friendlier than hand-rolling a schema transformer. To wrap resolvers, [middlewares](./middlewares.mdx) and [app plugins](../advanced/app-plugins.mdx) are usually a better fit: they run inside Baeta's middleware chain and don't rebuild the schema.

## Defining a directive

`src/modules/custom-native-directive/custom-native-directive.gql`

```graphql
directive @upper on FIELD_DEFINITION

type NameWithUpper {
  name: String! @upper
}

type Query {
  testUpperDirective(name: String!): NameWithUpper
}
```

## Implementing the directive

Write the directive as a schema transformer, here using `@graphql-tools/utils`:

`src/modules/custom-native-directive/upper-directive.ts`

```typescript
import { getDirective, MapperKind, mapSchema } from "@graphql-tools/utils";
import { defaultFieldResolver, type GraphQLSchema } from "graphql";

export function upperDirective(schema: GraphQLSchema) {
  return mapSchema(schema, {
    [MapperKind.OBJECT_FIELD]: (fieldConfig) => {
      const upperDirective = getDirective(schema, fieldConfig, "upper")?.[0];

      if (!upperDirective) {
        return fieldConfig;
      }

      const { resolve = defaultFieldResolver } = fieldConfig;

      fieldConfig.resolve = async (source, args, context, info) => {
        const result = await resolve(source, args, context, info);
        if (typeof result === "string") {
          return result.toUpperCase();
        }
        return result;
      };
      return fieldConfig;
    },
  });
}
```

Resolve the module's fields as usual:

`src/modules/custom-native-directive/index.ts`

```typescript
import { CustomNativeDirectiveModule } from "./typedef.ts";

const { Query, NameWithUpper } = CustomNativeDirectiveModule;

export default CustomNativeDirectiveModule.$schema({
  Query: Query.$fields({
    testUpperDirective: Query.testUpperDirective.resolve(({ args }) => {
      return {
        name: args.name,
      };
    }),
  }),
  NameWithUpper: NameWithUpper.$fields({
    name: NameWithUpper.name.key("name"),
  }),
});
```

Then apply the transformer to the application schema before handing it to your server:

`src/app.ts`

```typescript
import { createApplication } from "@baeta/core";
import { upperDirective } from "./modules/custom-native-directive/upper-directive.ts";
import sources from "./modules/index.ts";

const baeta = createApplication({ sources });

const schema = upperDirective(baeta.schema);
```

`@upper` makes string fields uppercase across the whole schema, including fields declared in other modules. The transformer wraps the compiled resolvers, so it runs outside Baeta's middleware chain: anything it does before calling `resolve` happens before auth, complexity and input validation.

## Usage

The directive transforms the result transparently:

```graphql
query {
  testUpperDirective(name: "hello") {
    name # Will return "HELLO"
  }
}
```

See the [GraphQL spec on directives](https://graphql.org/learn/execution/#directives) for the underlying semantics, and the [directives example](https://github.com/andreisergiu98/baeta/tree/main/examples/directives) for runnable code.
