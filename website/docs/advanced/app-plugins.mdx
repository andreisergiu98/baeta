# App Plugins

App plugins extend Baeta at the application level. They attach middlewares, read or set metadata across modules, and inspect the compiled schema. The built-in [authorization](./authorization), [complexity](./complexity) and [input validation](../guides/input-directives.mdx) features are themselves app plugins, and you can stack any number of them in a single app.

## Registration

Pass plugins to `createApplication`:

```typescript title="src/app.ts"
import { createApplication } from "@baeta/core";
import { authAppPlugin } from "./lib/auth.ts";
import { complexityAppPlugin } from "./lib/complexity.ts";
import sources from "./modules/index.ts";

const baeta = createApplication({
  sources,
  plugins: [complexityAppPlugin, authAppPlugin],
});
```

Using a plugin helper (e.g. `auth(...)`, `complexity(...)`) without registering the matching app plugin throws at startup, when `createApplication` builds the schema. No silent no-ops.

## Plugin ordering

The order in `plugins` matters. Two invariants:

1. **Registration order = setup order.** Each plugin's setup phase runs in array order, so later plugins can read metadata set by earlier ones.
2. **Earlier plugins wrap later ones at runtime.** Middlewares attached by the first plugin run _outside_ middlewares attached by later plugins. With `plugins: [A, B]` and a resolver `R`:

   ```
   A pre  →  B pre  →  R  →  B post  →  A post
   ```

   The first-registered plugin's pre-hook runs first; its post-hook runs last.

## Choosing an order

The order is your choice. Each plugin rejects a request at its own position, so the order decides which check a caller hits first.

A common setup authenticates before execution: creating the context throws for an invalid token and lets requests without one through as anonymous. The plugins handle the rest:

```typescript
plugins: [complexityAppPlugin, inputValidationAppPlugin, authAppPlugin],
```

- Complexity rejects over-budget queries before any other work runs.
- Input validation rejects invalid arguments, so auth rules see validated arguments.
- Auth checks permissions.

With `authAppPlugin` first, anonymous callers are rejected before complexity or validation runs, so they can't learn about the schema from those errors. The cost is running scope loaders for queries that complexity would reject anyway.
