# Built-in Directives

`@baeta/plugin-directives` ships a catalog of ready-made [input directives](../guides/input-directives.mdx) for the common cases: string, number and object validation. Enable the plugin, register the validation app plugin, and use the directives directly in your `.gql` files.

## Installation

import { PackageManagerAdd } from "@site/components/package-manager";

Runtime dependency:

<PackageManagerAdd package="@baeta/directives" />

Development dependency:

<PackageManagerAdd dev={true} package="@baeta/plugin-directives" />

## Setup

Add the directives plugin to your `baeta.ts` configuration:

```typescript
import { defineConfig } from "@baeta/cli";
import { directivesPlugin } from "@baeta/plugin-directives";

export default defineConfig({
  plugins: [directivesPlugin()],
  // ... rest of config
});
```

For the full configuration interface, see the [`DirectivesOptions`](/docs/api/plugin-directives/interfaces/DirectivesOptions) API reference.

The plugin generates a `baeta-directives` module that registers the directives. That module requires `inputValidationAppPlugin`, so add it to your application:

```typescript title="src/app.ts"
import { createApplication } from "@baeta/core";
import { inputValidationAppPlugin } from "@baeta/directives";
import modules from "./modules/index.ts";

const baeta = createApplication({
  modules,
  plugins: [inputValidationAppPlugin],
});
```

See [Plugin order](../guides/input-directives.mdx#plugin-order) when you also use auth or complexity.

## Available directives

### String validation

```graphql
directive @validString(
  maxLength: Int
  minLength: Int
  startsWith: String
  endsWith: String
  includes: String
  regex: String
  regexFlags: String
  oneOf: [String!]
  notOneOf: [String!]
) on INPUT_FIELD_DEFINITION | ARGUMENT_DEFINITION
```

Checks run in the order listed and stop at the first failure, so `maxLength` is enforced before `regex` is tested. Always pair `regex` with `maxLength`: the pattern runs on the server against client-supplied strings, and the length cap bounds the work a backtracking-heavy pattern can do.

### Number validation

```graphql
directive @validFloat(
  multipleOf: Float
  max: Float
  min: Float
  exclusiveMax: Float
  exclusiveMin: Float
  oneOf: [Float!]
  notOneOf: [Float!]
) on INPUT_FIELD_DEFINITION | ARGUMENT_DEFINITION

directive @validInt(
  multipleOf: Int
  max: Int
  min: Int
  exclusiveMax: Int
  exclusiveMin: Int
  oneOf: [Int!]
  notOneOf: [Int!]
) on INPUT_FIELD_DEFINITION | ARGUMENT_DEFINITION
```

### Object validation

```graphql
directive @constraints(minFields: Int, maxFields: Int) on INPUT_OBJECT
```

## Usage

```graphql
input UserInput @constraints(minFields: 2) {
  email: String! @validString(regex: "^[^@\\s]+@[^@\\s]+$", maxLength: 254)
  age: Int! @validInt(min: 18)
  name: String! @validString(minLength: 1, maxLength: 100)
  score: Float @validFloat(min: 0, max: 100)
}

type Mutation {
  createUser(input: UserInput!): User!
}
```

See the [directives example](https://github.com/andreisergiu98/baeta/tree/main/examples/directives) for a runnable setup.
